# xmoat · 护城河

**写给长期持有者的基本面 / 价值投资分析工具**

盯财报、估值、分红和雷区，不盯 K 线。
财报出来、估值进入你设定的区间时，归纳好推送给你。

基于 [xnet2lua](https://github.com/1dao/xnet2lua)（C 网络内核 + 内嵌 Lua）编写，一个运行时二进制加一目录 Lua 脚本，不需要 Python 环境。

## 定位

价值投资问的是生意和价格的关系，节奏跟着财报走，不跟着 K 线走：

| | 看 | 不看 |
|---|---|---|
| 关注什么 | 生意质量、财务健康、估值高低 | 价格走势、资金流向、市场情绪 |
| 数据节奏 | 财报按季更新，价格只用来算估值 | 盘中和每日的价格信号 |
| 输出 | 估值分位、安全边际、检查清单、雷区提示 | 买入价 / 止损价 / 目标价 |
| 什么时候提醒 | 发财报、发分红公告、估值穿过你设的区间 | 每个交易日例行推送 |

配套功能：自选股、定时运行、多渠道推送、Web 界面，以及可选的大模型归纳。
部署只要 `bin/xnet` 一个二进制加一目录 Lua 脚本，不需要 Python，也不需要 Node 前端构建。

## 它要回答的问题

**这是门好生意吗？**
- ROE、ROIC 连续多年的水平和稳定性，而不是单一年份
- 毛利率、净利率的波动：定价权通常先体现在毛利率上
- 利润含金量：经营现金流与净利润之比，自由现金流
- 负债结构：有息负债率、现金能覆盖多少短债

**现在贵不贵？**
- PE（TTM）、PB、PS 在自身 5 年 / 10 年历史里的分位
- 股息率、自由现金流收益率
- 反向 DCF：用现价倒推市场隐含的增长率，看这个增长率是否合理
- 你自己设定的合理估值区间，以及当前价格离它的安全边际

**股东拿到了什么？**
- 连续分红年数、分红率、回购

**有没有雷？**
- 存贷双高、应收账款或存货增速远超营收
- 经营现金流与净利润长期背离
- 商誉占净资产比例过高
- 大股东高比例质押、非标审计意见

**护城河在哪里？**（可选，需要配置大模型）
- 从年报「管理层讨论与分析」中归纳竞争优势及其变化，和上一年对比

## 设计原则

**数字由代码算，大模型不碰数字。** 所有财务指标和估值都是确定性计算，每个数字都能追溯到数据源的字段和报告期。
大模型只拿到算好的结果和原文段落，负责定性归纳和成文。原因很简单：大模型会把 12.3% 抄成 13.2%，而投资决策最怕这种错。
报告里规则算出的结论和大模型的判断分开展示，不混在一起打一个总分。

**报告期和公告日分开存。** 三季报的报告期是 9 月 30 日，但市场在 10 月底才看到。
按报告期对齐历史估值会引入未来数据，回看的结论会好得不真实。所有历史计算都按公告日取数。

**不同行业用不同的指标模板。** 银行、保险、券商没有有意义的毛利率，负债率高是经营常态；
对它们要看不良率、拨备覆盖率、净息差、内含价值。套用同一张检查清单会得出错误结论。

**不给买卖点位。** 输出估值区间、分位和安全边际，决定由你做。

## 技术栈

| | 用什么 | 为什么 |
|---|---|---|
| 运行时 | [xnet2lua](https://github.com/1dao/xnet2lua) | 事件循环、线程、定时器、HTTP/HTTPS 客户端和服务端都在一个二进制里 |
| 数据抓取 | `xhttp_client`（异步 HTTP/HTTPS） | 请求挂在事件循环上，多只股票并发拉取不开线程 |
| 定时任务 | `xtimerx` | 收盘后更新估值，财报季轮询公告 |
| 存储 | JSON 文件（默认）或 MySQL | 同一套接口两个后端，做法沿用 gitloom 的 `store.lua` |
| Web 界面 | 同源静态页面，无构建步骤 | 不需要 Node |
| 大模型 | OpenAI 兼容接口 | DeepSeek、通义千问、Gemini、Claude 等都能接 |
| 推送 | Webhook | 企业微信、飞书、钉钉、Telegram |

没有 Python 就用不了 AkShare，所以数据源都走 HTTP 接口直接对接（计划中，按优先级）：

| 市场 | 数据源 | 内容 |
|---|---|---|
| A 股 | [Tushare Pro](https://tushare.pro) HTTP API | 三张表、财务指标、每日估值、分红 |
| A 股 | [巨潮资讯](http://www.cninfo.com.cn) | 定期报告与公告原文 |
| A 股 / 港股 | 东方财富公开接口 | 行情与财务数据，作为补充 |
| 美股 | [SEC EDGAR](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) XBRL `companyfacts` | 官方财务数据，免费 |

工程约定沿用 [gitloom](https://github.com/1dao/gitloom)：
- 每个 `app/*.lua` 在独立环境中加载，只通过 `g_exports` 导出，导出名必须带模块前缀
- 配置先到先得：命令行 `KEY=VAL` > `xmoat.local.cfg`（存 token，不进版本库）> `xmoat.cfg`
- `scripts/core/` 是从 xnet2lua **复制**来的模块子集，不是 submodule
- `bin/` 不进版本库，运行时按平台从 xnet2lua 复制

```

    source_cninfo.lua
```

## 已知限制

- **数据源的稳定性不由本项目决定。** 东方财富等公开接口没有文档承诺，随时可能改字段或限流；Tushare 部分接口需要积分。数据源适配层就是为了能换源而存在的。
- **财报数据有错漏。** 第三方数据源对三张表的科目归类不完全一致，重述（追溯调整）也未必及时反映。关键结论请对照原始报告核实，报告里会给出报告期和来源以便核对。
- **指标对新上市、亏损或周期性公司意义有限。** 历史分位需要足够长的历史，PE 在亏损时无意义，周期股低 PE 往往出现在盈利顶点。
