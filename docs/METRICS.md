# 指标口径

每个数字从哪里来、怎么算、什么时候算不出来。实现分别在 `engine/` 下对应的文件里，
测试用例在 [test/unit.lua](../test/unit.lua)，大多附有手算过程。

## 数据源字段

来源是东方财富公开接口，字段映射集中在 [engine/source_em.lua](../engine/source_em.lua)。

| 数据集 | 接口 | 用途 |
|---|---|---|
| 主要财务指标（按报告期） | `RPT_F10_FINANCE_MAINFINADATA` | 营收、利润、ROE、ROIC、毛利率、负债率、银行指标 |
| 每日估值 | `RPT_VALUEANALYSIS_DET` | 收盘价、市值、PE(TTM)、PB(MRQ)、PS(TTM)、PCF(TTM) |
| 分红送配 | `RPT_SHAREBONUS_DET` | 每股派现、除息日、方案进度 |
| 资产负债表 | F10 `zcfzbAjaxNew` | 货币资金、应收、存货、商誉、借款（仅一般企业） |

单位约定：金额为元；ROE、利润率、负债率、增速为百分数（15.2 表示 15.2%）；
经营现金流 / 净利润是倍数（1.53 表示 153%）；每股派现为元/股（源数据是每 10 股，已除以 10）。

## 两个容易出错的地方

**累计值。** 一季报、中报、三季报里的营收和利润是年初至今的累计数，不是单季。
中报利润不能直接和年报比，四个累计数也不能相加。

**报告期和公告日。** 2025 年三季报的报告期是 9 月 30 日，市场 10 月底才看到。每期报告都保存了公告日
（`notice_date`）。历史估值直接用数据源每日计算的值，而不是用今天看到的报告回算过去，
这样不会把事后才公布、甚至事后追溯调整的数字带进过去的日期。

## TTM（近十二个月）

```
最新是年报：  TTM = 年报值
否则：        TTM = 最新累计 + 上一年年报 − 上年同期累计
```

例：2025 中报累计 50，2024 年报 100，2024 中报累计 40 → TTM = 110。
缺任何一期就不算，并在结果里说明缺哪一期。

## 估值分位

- 窗口：全部历史（数据源从 2018 年起）和近 5 年。
- 只统计正值。PE 为负表示亏损，不代表便宜；把亏损期放进样本，会让盈利年份看起来都偏贵。当前值为负时不给分位。
- 分位 = (低于当前值的天数 + 等于当前值的天数 / 2) / 样本天数 × 100。当前这一天本身也在样本里。
- 样本少于 240 个交易日（约一年）时不给分位。

## 反向 DCF

给定现价，反推市场隐含的增长率：

```
价值(g) = Σ(t=1..n) E(1+g)^t / (1+r)^t  +  E(1+g)^n (1+tg) / (r − tg) / (1+r)^n
求 g，使 价值(g) = 总市值
```

- E = 归母净利润（TTM），近似股东盈余。需要大量再投资才能增长的公司，真实可分配的现金更少，
  所以隐含增长率应当看作下限。
- r、tg、n 取自配置 `DCF_DISCOUNT_RATE`（默认 10%）、`DCF_TERMINAL_GROWTH`（3%）、`DCF_YEARS`（10 年），
  每个结果旁边都会显示。
- 用二分法在 −50% 到 100% 之间求解；超出范围时标注"低于"或"高于"。
- E ≤ 0 时不计算。

## 股息率与分红

- **股息率（近 12 个月）**：除息日落在最近 365 天内的每股派现合计 ÷ 最新收盘价。按除息日而不是报告期统计，
  因为股息率说的是持有人过去一年实际收到了多少。
- **年度分红**：按报告期所属年度汇总（中期和年末合计），分红率 = 年度每股派现 ÷ 当年年报基本每股收益。
- **连续分红年数**：从最近一个年报的年度往回数，遇到没有分红的年度就停。不从"最近一次分过红的年度"开始数，
  否则停止分红的公司看起来仍然连续。
- 方案进度为"停止实施""股东大会否决""不分配"的不计入；已宣布、尚未股东大会通过的方案计入对应年度，
  但在除息之前不计入股息率。

## 经营质量（年报）

只用年报，最多近 10 年。汇总项：

| 项 | 口径 |
|---|---|
| ROE 均值 / 最低 | 近 5 个年报的加权 ROE |
| ROIC 均值 | 近 5 个年报（一般企业） |
| 毛利率均值、波动幅度 | 近 5 个年报；波动幅度 = 最高 − 最低 |
| 经营现金流 / 净利润 均值 | 近 3 个年报 |
| 营收、归母净利润复合增速 | 最多近 6 个年报的首尾，标注实际跨度；首尾任一为负不计算 |

## 检查清单

每项结果为 通过 / 注意 / 数据不足。**数据不足不等于通过。** 阈值集中在
[engine/checks.lua](../engine/checks.lua) 顶部，也可以通过 `system.info` 取到。

**一般企业**

| 检查 | 提示条件 |
|---|---|
| 最近一个财年盈利 | 年报归母净利润 ≤ 0 |
| 利润有现金流支撑 | 近 3 个年报 经营现金流 / 净利润 均值 < 0.8 |
| 利润主要来自主业 | 扣非净利润 / 归母净利润 < 80% |
| 毛利率没有明显下滑 | 同比下降超过 5 个百分点 |
| 应收账款没有远快于营收 | 应收同比增速 − 营收同比增速 > 20pt，且应收 ≥ 营收的 5% |
| 存货没有远快于营收 | 存货同比增速 − 营收同比增速 > 30pt，且存货 ≥ 营收的 10% |
| 商誉占净资产比例不高 | 商誉 / 归母净资产 > 30% |
| 没有"存贷双高" | 货币资金 / 总资产 ≥ 15% 且 有息负债 / 总资产 ≥ 15% |
| 现金能覆盖短期有息负债 | 货币资金 < 短期借款 + 一年内到期的非流动负债 |
| 资产负债率不高 | 最新报告资产负债率 > 70% |

有息负债 = 短期借款 + 长期借款 + 应付债券 + 一年内到期的非流动负债。这是近似值：
不含租赁负债，而"一年内到期的非流动负债"里可能有不计息的项目。

**银行**

| 检查 | 提示条件 |
|---|---|
| 最近一个财年盈利 | 同上 |
| 不良贷款率不高 | 最新 > 2% |
| 不良率没有上升 | 最近两个年报之间上升超过 0.1 个百分点 |
| 拨备覆盖率充足 | 最新 < 150% |
| 核心一级资本充足 | 最新 < 8.5% |

**保险、证券**：目前只有盈利检查，专项指标尚未实现，分析结果里会说明。

## 提醒规则

提醒来自比较同一只自选股刷新前后的两份数据（[engine/events.lua](../engine/events.lua)）。
两边用同一份自选设置做分析，所以在两次刷新之间修改合理区间，不会被当成价格穿过了区间。
第一次抓取没有可比较的数据，不产生提醒。

| 类型 | 触发条件 |
|---|---|
| 财报 | 出现了之前没有的报告期。季报、中报的营收和利润标注为"累计" |
| 分红 | 出现了之前没有的"报告期 + 方案进度"组合，且有现金分红金额：董事会预案、股东大会通过、实施分配各提醒一次 |
| 你的区间 | 估值相对你设的区间的位置变了：低于 / 位于 / 高于 |
| 估值分位 | 全部历史分位从 ≥ 下限跌到 < 下限，或从 ≤ 上限升到 > 上限（默认 10% / 90%）。一般企业看 PE（TTM），银行看 PB。只在进入区域时提醒，一直处在区域里不重复提醒 |
| 检查清单 | 某项检查从"通过"变成"注意"，或反过来。"数据不足"的变化不提醒 |

每条提醒的 id 由股票和变化内容（报告期、方案进度、穿越发生的估值日期）决定，同一变化只记一次。

**推送。** 一次推送把所有待推送的提醒合成一条消息，按股票分组，最多列 20 条。至少一个渠道成功就算已推送；
所有渠道都失败时保留待推送，失败 3 次后放弃。推送时没有配置任何渠道，这些提醒标记为"未配置推送"，
以后配置了渠道也不会补发，避免一次收到几个月的旧提醒。

**定时检查。** 默认北京时间工作日 17:30，按 UTC 偏移计算，与服务器所在时区无关。每个时间点每天最多运行一次，
记录在 `data/state.json`；服务在当天错过的时间点之后启动，会补跑一次。节假日无法识别，但那天数据没有变化，不会产生提醒。
